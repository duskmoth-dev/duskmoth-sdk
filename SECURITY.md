# Security policy

Contact: hello@duskmoth.xyz. Start with a non-sensitive summary to arrange a secure channel.
Do not post exploit details, credentials, private keys, or private transaction data in a public issue.
No response-time commitment or bug bounty is implied.

## Release policy

An unresolved high/critical dependency finding, a detected credential, or a failing test blocks a stable release.
Passing automated checks is not an independent security audit or proof of anonymity.
Private transfers use third-party infrastructure. Provider failures and commercial terms must be reviewed separately.
Source snapshots and prereleases must not be described as audited or production-approved.
